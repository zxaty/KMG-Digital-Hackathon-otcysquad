# Навык: ИБ-08 — контроль выгрузки персональных данных

## Что проверить
1. Найди ВСЕ точки выгрузки: маршруты exports/*, download, csv/json/xlsx, «пакет для интеграции», API, отдающие справочник пользователей. Каждый формат — отдельно; не обобщай вывод по первому найденному.
2. Для каждой независимо:
   - серверная проверка роли «администратор» (не login_required, не is_staff, не токен — ТС 4.7.2: проверка одинакова для всех форматов и не заменяется токеном);
   - запись в журнал аудита в том же обработчике: дата/время, инициатор, формат, количество записей (ТС 4.7.3).
3. Состав полей — фиксированная схема (id, логин, ФИО, e-mail, роль); пароли, хеши, токены не выгружаются.
4. Ответ не кэшируется (`Cache-Control: no-store`), файл не сохраняется в общедоступный каталог, CSV защищён от формул (`=`, `+`, `-`, `@`, а также `\t`, `\r`) — несоответствия этим пунктам ТС 4.7.4 относятся к spec_gaps.

## Типичное нарушение
Соседние форматы одной выгрузки реализованы по-разному: CSV защищён ролью и пишет аудит, JSON — только login_required и без аудита.

## Не является нарушением
- API чтения собственных обращений для заявителя/оператора без справочника пользователей (ТС 4.7.5).
