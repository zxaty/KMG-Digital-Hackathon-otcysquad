# Навык: ИБ-05 — защита локальных журналов приложения

«Локальный журнал приложения» по ТС 1.21 — буфер событий аудита, который серверное приложение пишет до передачи сборщику событий. История обращения и журнал браузера — не он.

## Что проверить
1. Каждая запись шифруется аутентифицированным шифрованием (AES-GCM/ChaCha20-Poly1305/Fernet) с уникальным nonce; запись атомарна (временный файл + rename).
2. Где лежит КЛЮЧ журнала и кто может его прочитать. Если ключ лежит в каталоге журнала, который доступен непривилегированному пользователю на чтение, пользователь расшифрует, изменит и заново зашифрует записи — защита от модификации не обеспечена (ТС 4.6.7).
3. Права на каталоги: pending (неотправленные записи) не должен быть доступен на запись/удаление непривилегированному субъекту; received — без доступа. Сравни с правами на каталог ключей.
4. Сборщик: проверяет целостность каждой записи, изолирует повреждённые (исключение на одной записи не должно останавливать обработку остальных), сохраняет принятые без возможности незаметной подмены.
5. Диагностические журналы (LOGGING, FileHandler) не пишут секреты и ПД в открытом виде (ТС 4.5.6).

## Не является нарушением
- сам факт хранения записей на диске до отправки, если они зашифрованы и защищены правами.
