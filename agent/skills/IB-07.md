# Навык: ИБ-07 — журналирование действий пользователей и событий СУБД (сквозное)

Требование сквозное: оценивай ОБЩИЙ механизм и его ПОКРЫТИЕ всего проекта, а не наличие журналирования в отдельных функциях (ТС 4.6.2: точечные вызовы при отсутствии в остальных функциях — нарушение).

## Что проверить
1. Какой общий компонент пишет журнал: сигналы ORM (post_save/post_delete/m2m_changed), сигналы входа (user_logged_in/out/login_failed), middleware. Для каждого — к каким моделям/событиям он реально применяется (фильтры по app_label, sender).
2. Покрытие операций по ТС 4.6.4 — пройди по маршрутам:
   - вход/выход/отказ входа;
   - ЧТЕНИЕ: просмотр списков и карточек, скачивание вложений, чтение через API — сигналы ORM чтение не видят, нужен middleware или явная регистрация;
   - изменения: создание/изменение/удаление обращений, комментариев, вложений, пользователей, очередей;
   - пакетные операции: `QuerySet.update()/bulk_create()/delete()` не вызывают post_save — пакетная смена статусов должна регистрироваться явно со списком затронутых объектов;
   - назначение ролей, выдача прав на очереди, смена/сброс паролей;
   - каждая выгрузка;
   - отказы в доступе (PermissionDenied/403/401).
3. Журнал событий СУБД (ТС 4.6.5): установление/отказ соединения (`connection_created`), изменение структуры (миграции), изменение прав на файл БД (например, команда управления доступом к SQLite). Отсутствие любого механизма — нарушение.
4. Согласованность (ТС 4.6.6): событие пишется после фиксации транзакции (`transaction.on_commit`), отменённая операция не оставляет «успешного» события.
5. Содержимое записи (ТС 4.6.3): идентификатор события, время с часовым поясом, пользователь, тип операции, объект, РЕЗУЛЬТАТ, идентификатор запроса и источника. Отсутствующие поля — spec_gaps.

## Не является нарушением
- отсутствие журналирования в библиотечных модулях `src/helpdesk`, не подключённых к urls.py.
