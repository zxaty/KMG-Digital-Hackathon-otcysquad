# Навык: ИБ-02 — проверка сессии и токена на стороне сервера

## Что проверить
1. Все маршруты, включая `api/...`: есть ли серверная проверка сессии (login_required, middleware, миксин) или токена (разбор заголовка Authorization в теле или общем компоненте).
2. Анонимно допустимы только форма входа и статика (ТС 4.4.1, 4.9.3). Любой другой маршрут без проверки — нарушение, особенно если возвращает данные.
3. Токен API (ТС 4.4.7): проверяются подпись, СРОК ДЕЙСТВИЯ (`max_age` у `signing.loads` или сравнение `exp` с текущим временем), существование и активность учётной записи. Поле `exp`, которое кладётся в токен, но нигде не сравнивается с временем, — токен фактически бессрочный.
4. Пользователь и роль берутся из сессии/токена, а не из параметров запроса (ТС 4.4.4).
5. Сессия: срок не более 60 минут, cookie HttpOnly, выход — изменяющим запросом (ТС 4.4.2, 4.4.5).

## Типичные нарушения
- «каталог»/«публичный» API без аутентификации, отдающий обращения и e-mail;
- токен без проверки срока действия;
- проверка только при выдаче токена, но не при каждом обращении.

## Не является нарушением
- `csrf_exempt` на API, который аутентифицируется только заголовком Authorization (CSRF для bearer-токенов не применим);
- LoginView без login_required.
Отзыв токенов при смене пароля/роли (ТС 4.4.7) — несоответствие спецификации (spec_gaps), если сама проверка токена при каждом обращении есть.
