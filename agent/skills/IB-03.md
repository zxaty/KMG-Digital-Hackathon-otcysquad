# Навык: ИБ-03 — защита канала передачи данных

## Где искать конфигурацию
Не только settings.py: транспортный модуль (serve.py / proxy.json / nginx / Dockerfile / CI), код создания SSL-контекстов, клиентские вызовы requests/urllib.

## Что проверить
1. Версия протокола: минимум TLS 1.2 (`minimum_version`, `minimum_tls`, `ssl_version`).
2. Шифронаборы для TLS 1.2 — только ECDHE + AEAD (GCM/CHACHA20-POLY1305) (ТС 4.8.1). Набор вида `AES128-SHA` = RSA-обмен ключами + CBC + SHA-1 — слабый. Групповые строки `HIGH`, `ALL`, `DEFAULT` без исключений тоже допускают слабые наборы.
3. Незащищённый канал: HTTP-слушатель без принудительного перенаправления на HTTPS (`http_redirect: false`), `SECURE_SSL_REDIRECT = False`, cookie сессии/CSRF без Secure, `SECURE_HSTS_SECONDS = 0` (ТС 4.8.2).
4. Отключение проверки сертификатов: `verify=False`, `CERT_NONE`, `check_hostname = False`, `_create_unverified_context` (ТС 4.8.3).
5. Доверие к `X-Forwarded-Proto` только от транспортного модуля (ТС 4.8.4): проверь, что прокси перезаписывает заголовок, а бэкенд слушает только 127.0.0.1.

## Не является нарушением
- самоподписанный сертификат, создаваемый при первоначальной настройке (так предусмотрено ТС 4.8.3);
- внутреннее взаимодействие прокси и бэкенда по 127.0.0.1 без TLS (ТС 4.8.4);
- `SECURE_PROXY_SSL_HEADER` при прокси, который сам выставляет заголовок.
