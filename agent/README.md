# Агент проверки требований ИБ (ИБ-01…ИБ-08) — команда otcysquad

Версия **1.0.1**. Агент проверяет исходный код, конфигурацию, зависимости, CI и документацию проекта на соответствие восьми Требованиям ИБ из ТЗ хакатона (п. 4.5), формирует отчёт JSON + Markdown (п. 4.6) и управляет пайплайном кодом завершения (п. 4.3.3). Проверяемый проект не изменяется, запросов к пользователю нет.

## Требования к окружению

- Python **3.10+** (синтаксис проверен для 3.10 и 3.12, тесты запускались на 3.14; в CI задан 3.12). Только стандартная библиотека: `pip install` не нужен.
- `git` (для определения коммита).
- Ключ API модели — DeepSeek или Qwen (OpenAI-совместимый API). Без ключа доступен режим «только правила» (`--provider none`).

## Быстрый запуск

Из корня репозитория (проверяемый проект — текущий каталог):

```powershell
# Windows PowerShell
$env:LLM_PROVIDER = "deepseek"
$env:LLM_API_KEY  = "<ключ DeepSeek>"
python agent/main.py --project-root . --out-json report.json --out-md report.md
echo "Код завершения: $LASTEXITCODE"
```

```bash
# Linux / macOS
export LLM_PROVIDER=deepseek LLM_API_KEY=<ключ DeepSeek>
python3 agent/main.py --project-root . --out-json report.json --out-md report.md; echo "Код завершения: $?"
```

Qwen (Alibaba Cloud Model Studio):

```bash
export LLM_PROVIDER=qwen LLM_API_KEY=<ключ DashScope> \
       LLM_BASE_URL=https://<WorkspaceId>.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1 \
       LLM_MODEL=qwen-plus
python3 agent/main.py --project-root . --out-json report.json --out-md report.md
```

Без модели (только детерминированные правила — быстро, без внешних сервисов):

```bash
python3 agent/main.py --project-root . --provider none --out-json report.json --out-md report.md
```

## Коды завершения (ТЗ 4.3.3)

| Код | Значение | Отчёт |
|---|---|---|
| `0` | нарушений Требований ИБ не выявлено — пайплайн продолжается | есть |
| `1` | выявлено ≥ 1 нарушение — слияние и развёртывание блокируются | есть |
| `2` | проверка не выполнена: модель недоступна, лимиты, нет ключа, ошибка разбора проекта | **нет** (ТЗ 4.7.3) |

При превышении дедлайна отчёт формируется в объёме выполненного: требования, не успевшие к модели, получают статус `not_checked`, находки правил по ним сохраняются (ТЗ 4.7.2). Несоответствия технической спецификации выводятся отдельным разделом и на код завершения не влияют (ТЗ 4.8.1).

## GitHub Actions

Workflow [`.github/workflows/ib-check.yml`](../.github/workflows/ib-check.yml) (`name: ib-security-check`):

- запускается по `push` (любая ветка) и вручную (`workflow_dispatch`, без параметров); `pull_request` / `pull_request_target` не используются;
- одна job `ib-check` (отдельный шаг «Run IB agent»); job `deploy` в workflow нет — в реальном пайплайне её ставят после `ib-check` с `needs: ib-check`;
- агент проверяет весь рабочий каталог коммита, на который пришёл push (`GITHUB_SHA` — он же `meta.commit` отчёта);
- лимит шага агента `timeout-minutes: 30` (job — 35), внутренний дедлайн агента — 25 минут;
- `report.json`, `report.md` и `agent-step.log` публикуются артефактом `ib-security-report-<sha коммита>` при любом исходе, кроме отмены run (`if: ${{ !cancelled() }}`, ТЗ 4.3.4); при коде 2 отчёта нет (ТЗ 4.7.3), публикуется только журнал;
- в журнале шага и в Summary — код завершения, число нарушений и перечень нарушенных требований (ТЗ 4.3.5);
- последний шаг переводит код агента в результат job: 0 — успех, 1 — блокировка, 2 (и шаг, прерванный без кода) — блокировка с сообщением «проверка не выполнена»;
- права токена минимальные (`permissions: {}`, для job — только `contents: read`), actions закреплены по полному SHA коммита.

Настройка репозитория: **Settings → Environments → создать environment `ib-check`**, в нём:

- secret `LLM_API_KEY` — ключ модели;
- variables `LLM_PROVIDER` (по умолчанию `deepseek`), при необходимости `LLM_MODEL`, `LLM_BASE_URL`.

Без секрета `LLM_API_KEY` (или при недоступности модели) агент завершается с кодом 2 и пайплайн блокируется — «проверка не выполнена» считается непрохождением (п. 3.3 состава материалов), тихого прохода в режиме «только правила» нет.

Локально ключ можно положить в файл `.env` (в текущем каталоге или в `agent/`; строки `KEY=VALUE`, уже заданные переменные окружения не перезаписываются). `.env` внесён в `.gitignore`; файл `.env` проверяемого проекта агент не читает.

```

  tech_spec_findings.py   детерминированные замечания ТС (попытки входа, парольная политика, отзыв токенов)

  llm_client.py           OpenAI-совместимый клиент (DeepSeek/Qwen/…) на стандартной библиотеке

  tests/                  119 тестов: индексатор, правила, клиент (фейковый сервер), CLI сквозные, эталонная фикстура
  reports/                образцы отчёта и журнала шага
  docs/Подход.md          описание подхода (п. 1.4 состава материалов)
```

## Безопасность

- Исходный код проверяемого проекта передаётся выбранному провайдеру модели (ТЗ 4.9.2 — допустимость определяет организатор). Режим `--provider none` не передаёт код никуда.
- Все текстовые поля отчёта проходят удаление секретов (пароли, токены, ключи, длинные hex-строки); коммит сохраняется как есть.
- Ключ API читается только из переменных окружения/секретов CI и не пишется в журнал.
