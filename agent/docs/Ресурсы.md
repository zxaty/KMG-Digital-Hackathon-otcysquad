# Ресурсы одной проверки (п. 1.5 состава материалов)

Тестовый проект: AlmasNUR/KMG-Digital-Hackathon, коммит `576e58100d7ef832cef2ad3ec73fc89ab98f84b5` (453 файла).

## Измерено

| Этап | Время |
|---|---|
| Индексирование всего проекта (AST, инвентарь, docx) | 0,8 с |
| Детерминированные правила ИБ-01…08 и ТС | 1,2 с |
| Полный прогон в режиме «только правила» (`--provider none`), включая отчёт | 2 с |

Размер запроса к модели по требованиям (системная подсказка + навык + находки правил + индекс + исходники), измерено на этом проекте:

| Требование | Символов | Токенов (оценка, ≈ символы / 3,2) |
|---|---|---|
| ИБ-01 | 55 000 | ≈ 17 200 |
| ИБ-02 | 51 300 | ≈ 16 000 |
| ИБ-03 | 33 400 | ≈ 10 400 |
| ИБ-04 | 57 600 | ≈ 18 000 |
| ИБ-05 | 39 500 | ≈ 12 400 |
| ИБ-07 | 54 900 | ≈ 17 200 |
| ИБ-08 | 41 500 | ≈ 13 000 |
| **Итого, 7 вызовов** | **333 300** | **≈ 104 000** |

ИБ-06 проверяется без модели.

## Оценка для прогона с моделью

- Входящие токены: ≈ 104 тыс. + до ≈ 40 тыс., если модель запросит дополнительные файлы (второй раунд, не более одного на требование).
- Исходящие токены: ≈ 1–3 тыс. на требование, ≈ 7–20 тыс. всего (больше у «думающих» моделей).
- **Итого ≈ 110–165 тыс. токенов на проверку.**
- Время: 7 запросов, до 3 одновременно (3 «волны»). При 30–120 с на запрос — ≈ 2–6 минут. Гарантированный верхний предел — внутренний дедлайн 25 минут, job — 30 минут (ТЗ 4.7.1).

Фактические значения каждого прогона записываются агентом в раздел `resources` отчёта (`llm.calls`, `prompt_tokens`, `completion_tokens`, `total_tokens`, `retries`, `wall_seconds`) и в `meta.duration_seconds`. После первого прогона с ключом замените оценку выше измеренными цифрами из артефакта.
